# ACPWB — Claude Code Context

## What This Project Is

A Django fake corporate website with two purposes:
1. **Email honeypot** — generates random `@acpwb.com` employee emails on the contact page and logs every visit for matching against inbound spam.
2. **AI bot poisoning** — structural/semantic/interactive honeypots designed to waste crawlers, poison training data, and watermark scraped content.

**GitHub:** git@github.com:dsilvers/acpwb.git  **Domain:** acpwb.com  **Founded:** 2006, Milwaukee WI

---

## Tech Stack

Django 5.2 LTS + Python 3.14 / PostgreSQL 16 / Bootstrap 5 (CDN) / Docker Compose (web + db + edge + redis + ws) / `acpwb_edge` Go TLS front-end (replaced nginx) / Redis 7 (pub/sub) / Cloudflare Email Routing + Mailgun (legacy)

## Running Locally

```bash
docker compose -f docker-compose-local.yml up --build   # https://localhost:8001 (self-signed, via acpwb_edge), admin at /django-admin/
docker compose exec web python manage.py collectstatic --noinput  # after static changes
docker compose exec web pytest  # run tests
```

## Key Models

- `people.PeoplePageVisit` — every load of `/our-people/`
- `people.GeneratedEmployee` — the fake employees shown (FK → visit)
- `honeypot.CrawlerVisit` — all bot/trap activity; `trap_type` choices: `report_list`, `report_download`, `ghost_link`, `dataset`, `api`, `well_known`, `scanner_probe`, `env_probe`, `wp_probe`, `webshell_probe`, `canary_trigger`, `source_code`, `source_code_download` (the .ARC/.ZIP/.tar.Z archive downloads off a source-code page), `compliance`, `compliance_certificate`; `host` field for per-subdomain breakdown; timestamp is `default=timezone.now, editable=False` (NOT `auto_now_add`) so Redis-queued records preserve request time
- `honeypot.ArchiveVisit` — archive trap hits; same timestamp pattern as CrawlerVisit
- `honeypot.CanaryToken` — canary URLs embedded in fake config files; `token_type` in `env_url`, `wp_config`, `git_config`
- `honeypot.InternalLoginAttempt` — credential-stuffing log: ip, ua, username, password, next_url
- `honeypot.WikiPage` — generated wiki content with watermark tokens
- `honeypot.PublicReport` — generated report metadata, persisted on first access
- `honeypot.IPIntelligence` — one row per distinct IP, MaxMind GeoLite2 geo/ASN + best-effort hosting/Tor heuristics; joined to CrawlerVisit by IP value only, never an FK (hypertable)
- `honeypot.RequestFingerprint` — residential-proxy-detection raw signal (header presence, client-negotiated protocol, TLS protocol/cipher, first-seen-IP flag); one row per request, queued via Redis and drained like CrawlerVisit — see `apps.core.signal_capture`/`apps.core.stream_middleware`
- `honeypot.IPReputationScore` — rule-based residential-proxy/automation score per IP, computed by `score_ip_reputation` from RequestFingerprint + CrawlerVisit + IPIntelligence; internal only (`evidence` field), see `apps.core.reputation_scoring`
- `honeypot.PublishedIPReputation` — external-facing classification + confidence only (no evidence), synced from IPReputationScore by `publish_ip_reputation`; what `/reputation-api/ip/<ip>/` reads
- `honeypot.SourceCodeEmail` — one row per (programmer address, source-code page) pair shown by acpwb_go; queued via `acpwb:code_email_queue`, drained by `drain_code_email_queue`; lets `_match_honeypot` trace inbound spam back to the page
- `honeypot.ComplianceCompletion` — /compliance/ milestones only (`completed` / `certificate` / `certificate_pdf` / `identified` = learner name/email/employee ID typed in), with answers string, score, pass, cert ID, learner fields, and `bot_type` / `client_class` (acpwb_go botclassify + the edge's X-Traffic-Class; blank before migration 0032); acpwb_go queues each (ip, course, attempt, event) at most once per 30 days on `acpwb:compliance_queue`, drained by `drain_compliance_queue`. Per-question answers are NOT stored: the CrawlerVisit path holds the whole trail (`acpwb_go compliance-score <path>…`, or paths on stdin, decodes it) Per-page stats are NOT rows: acpwb_go `visitqueue.PushComplianceStats` keeps per-UTC-day Redis counters `acpwb:cstat:<YYYYMMDD>:<name>` (45 days: pages by kind and kind|class, bots, topics, exhibits, depth, agencies zset, ips/att:<d>/fan:<d> HyperLogLogs for fan-out), read by `apps/core/compliance_stats.py` for the staff dashboard `/acpwb-dashboard/compliance/` (score vs. ~26% random guessing per agent, funnel, crawl fan-out, certificate leaderboard, typed-in learners, mail to harvested instructor addresses).
- `honeypot.EdgeConnection` — one row per client connection accepted by acpwb_edge, failed TLS handshakes included: `conn_id`, SNI/ALPN/TLS version+cipher, outcome, JA4/JA4_r/JA3/JA3 string/h2 fingerprint, RTT, bytes, request/unserved counts, first client ID + first-request summary; requestless connections from one IP past `EDGE_RECORDS_PER_IP_MINUTE` are folded into `aggregated` rows (count with `Sum('conn_count')`); TimescaleDB hypertable (no PK; `idempotency_key`+`timestamp` unique), queued via `acpwb:edge_conn_queue`, drained by `drain_edge_conn_queue`
- `honeypot.EdgeRequest` — one row per HTTP request seen by acpwb_edge: every request, static files/redirects included, and failed ones (`error`: rejected by the HTTP server, `h2_not_served`, `client_closed`, upstream errors, `plain_on_tls`…); method/host/path/query/UA/referer/header order/JA4H, status, route, bytes, TTFB, duration. Links: `conn_id` → EdgeConnection, `request_id` (forwarded as `X-Request-Id`, stored as `request_id` on CrawlerVisit/ArchiveVisit/RequestFingerprint via `apps.core.request_id`), `client_id` = the edge's signed first-party `acpwb_cid` cookie (one browser across connections/IPs). Classified per request by the edge: `client_class` (`known_bot`/`tool`/`browser`/`headless`/`impersonator`/`unknown`; `headless` = a real browser engine that's automated: a browser claim from a hosting network, a HeadlessChrome client hint, or a hidden-link hit; `browser` = a real engine on a home network — not proof of a person, since on this site nearly all of it is proxy-driven), `stack` (the real TLS client), `network` + `asn`, `signals` bitmask (names in `apps/core/traffic_signals.py`), `ja4`. Hourly-chunk hypertable (all four hypertables use 1-hour chunks, compressed after 6 hours), queued via `acpwb:edge_request_queue`, drained by `drain_edge_request_queue`
- `honeypot.EdgeIPHour` / `honeypot.EdgeFingerprintHour` — hourly rollups of the edge tables, built by `rollup_edge_hour` (kept forever; daily/weekly-chunk hypertables): per client IP (requests by client class, static/error/cookie counts, trap hits from CrawlerVisit, no-hello and failed-handshake connections from EdgeConnection — IPs with only those get rows with requests = 0, distinct JA4s/UAs, top stack, OR of signals) and per JA4 + HTTP/2 fingerprint (conns, IPs, residential/hosting IPs, single-connection IPs = rotation, class counts, top UA). Distinct counts are per hour — summing `ips` over hours gives IP-hours. Also `page_reqs` (GETs to django/acpwb_go), `pool_cookie_reqs` (requests carrying a cookie seen on `POOL_IPS`=3+ IPs that hour) per IP, and `trap_reqs`/`trap_ips` per fingerprint (CrawlerVisit trap hits joined by `request_id`, so CGNAT can't smear them). Per IP, `bare_page_reqs` (browser page loads from an IP that fetched no assets and returned no cookie all hour — browser farms fetching documents with subresources blocked; the edge can't tell per request) and `behaviour_proven_reqs` (its browser/unknown requests when bare loads, a trap or a pool cookie convict the IP); the dashboard headline "Proven Automated" is the last 3 rolled-up hours, class + behaviour, with the 24h figure beside it. Dashboard "Who's Really Visiting" / "Caught by Behaviour" panels and (planned) reputation scoring read these, not the raw tables
- `honeypot.EdgeClientHour` — hourly rollup per `acpwb_cid` client cookie, only for cookies sent back at least once that hour (one-request clients are most bots and a million an hour). A cookie is one browser profile where an IP is many (CGNAT), so behaviour shows here: `ips` ≥ 3 in an hour = a proxy pool sharing one cookie jar; `first_seen` + `page_reqs` ≥ 2 + `static_reqs` = 0 = not rendering pages; `trap_reqs` > 0 = convicted. Daily-chunk hypertable (migration 0028), built first in each `rollup_edge_hour` run (the IP rollup reads its pools)
- `webhooks.InboundEmail` — received emails; attachments aren't stored separately — `apps/webhooks/replies.py` reads them from `raw_payload['raw']` (Cloudflare deliveries only)
- `webhooks.OutboundEmail` — replies sent from the dashboard email detail page (inbox: `/acpwb-dashboard/emails/inbox/`, paginated, one search box over sender/recipient/subject/body) (`replies.send_reply`, Django SMTP backend → Mailgun; From is any `@acpwb.com` address, defaulting to the one the mail was delivered to). Needs `MAILGUN_SMTP_LOGIN`/`MAILGUN_SMTP_PASSWORD` in `.env`; without them mail goes to the console backend
- `webhooks.HoneypotMatch` — links inbound email to the visit that generated the address (`generated_employee`/`original_visit`) or the source-code page that showed it (`source_code_email`)

## Honeypot Techniques

Every page injects ghost links (`position:absolute; left:-9999px`), prompt-injection span (`font-size:0`), and garbage JSON-LD with watermark token.

Key traps and their `trap_type`:
- **Archive subdomains** `archives-YYYY.acpwb.com` (1985–2024) — infinite recursive content, era-themed; routed via `SubdomainMiddleware` → `apps.honeypot.archive_subdomain_urls`. Also served at `/archive/<year>/...` on main domain (no redirect). `_archive_url()` dispatches: subdomain same-year → relative, subdomain cross-year → absolute subdomain URL, main domain → `/archive/<year>/...`
- **Yearless archive** `/<month>/<day>/...` on main domain — bots copying subdomain paths verbatim; year derived deterministically from slug hash → `archive_trap_yearless()`
- **Scanner traps** — `/.env`, `/wp-config.php`, `/wp-login.php`, `/xmlrpc.php`, `/*.php` catch-all, `/.git/config`, `/.htpasswd`; respond as if exploit worked; log to `env_probe` / `wp_probe` / `webshell_probe`
- **Internal portal** `/internal/` — fake intranet; `/internal/login/` logs credentials; employee records, salary DB, acquisition targets all with CSV export
- **Wiki** `/wiki/<slug>/` — subtly wrong watermarked facts, 60+ topics
- **Reports** `/reports/` — fake research archive, infinite scroll, watermarked CSV/PDF
- **Datasets** `/datasets/` — 8 fake NLP datasets, paginated JSONL
- **Feeds** `/feeds/archive.xml`, `/feeds/reports.xml` — infinite paginated Atom/RSS
- **Canary ping** `/.well-known/tokens/<token>/ping` — self-hosted callback embedded in fake config files; `secrets.token_urlsafe(32)` token created at serve time
- **Compliance training** `/compliance/` (`acpwb_go/compliance`, edge route `/compliance/` → acpwb_go; Go-only, no Python mirror or fixtures) — the ACPWB ComplianceCenter, an endless fake LMS. Courses live under their mandating agency: `/compliance/<agency slug>/` lists the agency's courses (agencies = the 853 real policy agencies plus ~43k generated regulators `<region>-<body>-<domain>`, e.g. `wi-board-workplace-ergonomics` → "Wisconsin Board of Workplace Ergonomics", from `compliance/data/bodies/`; region/body slugs have no hyphens so they parse back), `/compliance/<agency>/<course-type slug>-<5 digits>/` is a course (the agency is part of its identity — `Course.ID` = `<agency>/<slug>` seeds everything; same type+number under another agency is another course). Test state lives in the path: `/compliance/<agency>/<course>/attempt-<k>/<answers>/` where `<answers>` is one letter (a–e) per question answered; every choice is a plain `<a href>` appending a letter, so crawlers take the test by following links and reach `…/<answers>/` results, `…/certificate/` and `…/certificate.pdf` (hand-written PDF, `compliance/pdf.go`). Optional learner details (`?n=&e=&id=`) ride along on every link; an anonymous certificate is issued to a recognized crawler by name ("OpenAI GPTBot (Unverified Learner)"), otherwise its name line is left blank. Hubs: `/compliance/` catalog (Available Trainings — self-paced/open-enrollment wording, deliberately no overdue/"action required" pressure so it doesn't read as phishing — Recommended, Elective, New & Updated, Renew a Certificate, all topics, featured agencies; endless `?page=`), `/compliance/agencies/?page=` (directory of every agency), `/compliance/topics/`, `/compliance/topic/<type>/`, `/compliance/verify/<agency>/<course>/<cert>/` (any 8-hex ID verifies), `/compliance/transcript/`, `/compliance/sitemap.xml` (a sitemap index of `sitemap-1..200.xml`). Content: `compliance/data/course_types.txt` (slug | title | code prefix | questions | pass mark | category:weight mix | blurb — new lines are new courses), `data/questions/<category>.txt` banks (`Q:` / `+` right / `-` wrong; 2+ `+` lines allow "All of the above"). ## Key Design Decisions

- **SubdomainMiddleware** sets `request.urlconf = 'apps.honeypot.archive_subdomain_urls'` for `archives-YYYY.acpwb.com`; runs before CSRF; catch-all `<path:rest>` pattern redirects non-archive paths to main domain; `site_root` context var = `https://acpwb.com` on subdomains so header/footer links always point to main domain
- **`?__year=YYYY` DEBUG shortcut** — activates archive subdomain mode without DNS; `pytest.ini` has `django_debug_mode = true` for archive tests
- **`handler404`** → `apps.honeypot.views.scanner_probe_404`; bypassed by Django debug 404 page — test with `@override_settings(DEBUG=False)`
- **`.php` URL ordering** — `wp-login.php`, `xmlrpc.php`, `wp-config.php` must appear before `re_path(r'^.*\.php$')` catch-all in `urls.py`
- **`psycopg[binary]`** (psycopg3) not psycopg2 — avoids Python 3.14 C-extension build issues
- **`RequestStreamMiddleware` is outermost** in `MIDDLEWARE` — measures end-to-end time; publishes to Redis `request_stream`; 30s circuit breaker; never affects HTTP response if Redis is down
- **PERCH conference year rollover** — `CURRENT_YEAR` in `apps/public/conference_data.py` drives `/perch-conference/`; earlier years auto-move to `/perch-conference/<year>/`. Templates read `conf.*` / `perch_year` (context processor `apps.public.context_processors.perch_context`). To roll over: add the new year's entry, flip the old one to `registration_open: False` + past tense + `attendees`, add a row to the dinner-history list in `conference_dinner.html`, and replace the hardcoded `PERCH <year>` footer label in `templates/jinja2/` and `acpwb_go` (`shell/shell.go`, `data/POLICY_FOOTER_TEMPLATE.html`, `policy/testdata/` fixtures — Go must byte-match Python output)
- **Live stream** uses standalone asyncio WS service (`ws_service/`) — not Django Channels; acpwb_edge routes `/ws/requests/` to it; token auth via `?token=` query param; without `STREAM_WS_TOKEN` IPv4s are sent last-octet-censored

## Residential Proxy Detection

Second product line in progress: catalog/score traffic for a future real-time blacklist/data feed. ~95% of traffic falls into `bot_type = 'Other / Browser'` (spoofed browser UA over a real residential IP), which UA/IP-range matching alone can't catch.

- **Signal capture** (`apps/core/signal_capture.py`, `apps/core/stream_middleware.py`) — runs on every request, not just UA-matched bot traffic: header-presence fingerprint against a fixed candidate list (`BROWSER_SIGNAL_HEADERS`), client-negotiated protocol + TLS protocol/cipher + JA4/JA3/JA4H/HTTP2 fingerprint (forwarded by acpwb_edge via `X-Client-Protocol`/`X-TLS-Protocol`/`X-TLS-Cipher`/`X-JA4`/`X-JA3`/`X-JA4H`/`X-H2-Fingerprint` — the edge proxies to the apps over plain HTTP/1.1, so these must be forwarded explicitly; it strips any client-sent copies first), first-seen-IP flag (self-expiring Redis key, `check_first_seen_ip` in `apps/core/crawler_queue.py`). Queued via `acpwb:fingerprint_queue` → `drain_fingerprint_queue` → `honeypot.RequestFingerprint`, same pattern as CrawlerVisit. Implemented in both Django and `acpwb_go` (`visitqueue.PushVisit`) — `acpwb_go` serves the highest-volume traffic, so skipping it would recreate the `backfill_bot_types` blind spot.
- **Scoring** (`apps/core/reputation_scoring.py`, `score_ip_reputation`) — pure, testable rule functions (`compute_score`, `looks_like_modern_browser`) combine header/protocol/TLS mismatch signals with cross-trap taint (`ABSOLUTE_PROOF_TRAP_TYPES` — `ghost_link`/`canary_trigger`/probe endpoints; hitting these proves automation regardless of what the rest of that IP's traffic looks like) and `IPIntelligence.is_hosting` (datacenter vs. residential ASN) into `honeypot.IPReputationScore`. `score_version` guards against silently redefining old rows' meaning.
- **External surface** (`publish_ip_reputation`, `/reputation-api/ip/<ip>/`) — `honeypot.PublishedIPReputation` deliberately exposes only classification + confidence, decoupled from `IPReputationScore`'s internal evidence, so the detection logic can change freely without breaking an external contract. `IP_REPUTATION_API_KEY` setting; fails closed (401) when unconfigured.
- **acpwb_edge** (`acpwb_edge/`, `deploy/acpwb-edge.service`) — Go TLS front-end that replaced nginx (and the old local-dev HAProxy) on :443/:80. Accepts TCP itself, parses the raw ClientHello (`tlsfp`: JA4, JA4_r, JA3 — even for handshakes that then fail), terminates TLS 1.0–1.3 (h2 only offered to TLS 1.2+/AEAD-capable clients), and taps the decrypted stream (`httpfp`: HTTP/1 header order → JA4H; HTTP/2 frame parser with its own HPACK decoder → Akamai-style `SETTINGS|WINDOW_UPDATE|PRIORITY|pseudo-header` fingerprint + per-stream header order, matched to handlers via `Claim`). `router` is a line-by-line port of `nginx/acpwb.com` + `nginx/botseed.net` with nginx's location precedence (regex in file order beats prefix; pinned by `router_test.go`) — any routing change goes there now, not in `nginx/`. Its own responses say `Server: acpwb/web` and use plain IBM HTTP Server-style error/redirect pages (`page`); plain HTTP on :443 is redirected to HTTPS (same host only for our names). One record per connection and one per request (`edgequeue`, one lane per kind with separate drop counters → `acpwb:edge_conn_queue`/`acpwb:edge_request_queue` → `EdgeConnection`/`EdgeRequest` hypertables; dashboard `/acpwb-dashboard/edge/`). Requests the HTTP server rejects before any handler runs are recovered from the taps (`H1Conn.Unserved`/`H2Conn.Unserved`) at connection close. Sets the `acpwb_cid` client cookie (HMAC-signed with `EDGE_COOKIE_SECRET`, Domain=acpwb.com / botseed.net, 1 year, Secure/HttpOnly/Lax) — it's in the cookie policy, so changes to it need a policy update. No per-client limits of any kind: the site exists to give bots unthrottled access. Certs: certbot still issues/renews; `deploy/certbot-deploy-hook.sh` copies to `/etc/acpwb-edge/certs/` and SIGHUPs. `nginx/` is kept only as the production rollback until the edge has run stably. **Request classification** (`acpwb_edge/classify`, ~2µs/request + one mmdb lookup per connection): checks the UA's browser claim against the TLS stack (`stacks.tsv`, keyed by JA4 cipher hash: Chromium, Firefox, Apple, Go, OkHttp, rustls), first ALPN, HTTP/2 pseudo-header order/window and, for Chromium, request header order (`classify/headers.go`: Chrome 155's navigation and subresource orders, captured through the edge; injected headers such as an early accept-language fail it), plus the client network from GeoLite2-ASN (`EDGE_ASN_DB`, SIGHUP reloads; hosting keywords mirror `ip_intel_classify.py`, pinned by a test). Chromium claims must also carry `sec-ch-ua` client hints that agree with the UA (Chromium brand version = `Chrome/` major, `sec-ch-ua-mobile` vs "Mobile", platform; `classify/hints.go`) — a `HeadlessChrome` brand is `headless` on any network. A request to a hidden-link-only section (`/internal/`, `/employees/`, `/admin-panel/` — same prefixes as Django's `ghost_link`) sets `hidden_link` and makes an otherwise genuine browser `headless` ("automated Chrome (hidden link)"). Self-named crawlers outside the bot list ("compatible; NameBot/1.0; +https://…") are `known_bot`, non-`Mozilla/` UAs `tool`; `x-middleware-subrequest` (Next.js auth-bypass probe) sets a signal. A contradicted claim is an `impersonator` ("Residential · fake Chrome (Go TLS)"). Labels go to EdgeRequest, the live view (`label`/`group` in the record, used by `ws_service`), and upstream as `X-Traffic-Class`/`X-Client-Asn`. `acpwb_edge/botclassify` is a byte-identical copy of `acpwb_go/botclassify` (a test fails on drift). Per request only: proxy-pool rotation needs aggregates (planned: hourly rollups → reputation scoring v2). **Not implemented:** JA4T/JA4TS (needs SYN capture), JA4S/JA4X, QUIC/HTTP3, and any JA4-based scoring rule (capture first, calibrate on real data).
- Everything above is fire-and-forget off the request path (same circuit-breaker/spawn pattern as `RequestStreamMiddleware`) — no synchronous scoring, lookups, or DB/Redis read-modify-write ever happens inline with a response.
